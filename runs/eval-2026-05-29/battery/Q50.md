# Q50 — the quality battery (medium-hard coding, hidden verification)

**Why this exists.** Core-50 is *saturated*: the byteshape speed champion and the
UD-IQ4_XS runner-up both score a perfect 50/50 + K 8/8. Core-50 measures tool-call
reliability we no longer doubt; it can no longer see **code quality**. Q50 is a new,
frozen, 50-task battery of medium-hard coding tasks designed so the champion scores
only ~20–35/50 — restoring headroom so a *better brain* can distinguish itself.

Campaign goal: `launch-drafts/goal_quality_champion_2026_07_21.md`.

## Method — hidden verification (the quality axis)

Each task is `fixtures/Q<nn>/` (a small buildable project the model sees) + a
`prompts/Q<nn>.txt` written in a **real user's voice** (states the goal, shows one
example, does *not* enumerate edge cases) + `verify/Q<nn>.sh` that **injects hidden
reviewer tests at grade time** and builds/runs them against the model's mutated copy.

- The fixture ships **only happy-path visible tests** (so the model has something to
  run and can believe it's done). The discriminating edges are **never** in the fixture.
- `verify/Q<nn>.sh` writes its hidden tests into the workdir, compiles + runs them, and
  prints exactly one `RESULT: PASS|FAIL — …` line (contract in `verify/_lib.sh`).
  It grades **what the model did to the code**, not what it said (no transcript grep).
- A PASS is only possible if the model handled the *unstated* edges the prompt implies
  — that is the code-quality signal. A 30/50 model nails the happy path and misses an
  edge; a 50/50 model handles the edge too.

## Test-first authoring gate (non-negotiable)

`refsol/Q<nn>/` holds a **reference solution** (overlay files that make the fixture
correct). It lives OUTSIDE the fixture; the model never sees it. Before a task may enter
`manifest-q50.tsv`, `gate_q50.sh <id>` must show:

1. **untouched fixture → verify FAIL** (the edge tests really bite), and
2. **fixture + refsol overlaid → verify PASS** (the task is solvable and the tests fair).

`bash gate_q50.sh` (no args) re-gates every `fixtures/Q*`. Run it before every freeze.

### Rust fixture gotcha
Every Rust fixture `Cargo.toml` MUST include an empty `[workspace]` table, else the
parent repo workspace (`D:\dev\claudette\Cargo.toml`) captures it and `cargo test`
errors with "believes it's in a workspace when it's not". Hidden tests go in
`tests/hidden_gate.rs` (integration test → uses only the crate's public API), run with
`cargo test --test hidden_gate` so the model's own unit tests can't interfere.

## Calibration + freeze protocol

1. Full Q50 on the crowned config (`champ-bs-mtpgpu2-lms`, ctx 32768), tag `q50-champ-bs306`.
2. Triage every FAIL: harness/fixture bug → fix the task; genuine quality miss → keep.
   0–1 s "failures" are template/load, not the model — check `logs-<tag>/` first.
3. **Discrimination gate:** champion baseline must land in **20–35/50**. >40 → harden the
   weakest tasks; <15 → ease. Iterate, then **FREEZE** (record freeze date + baseline here).
4. Second free calibration point: full Q50 on UD-IQ4_XS (already on disk).

## Crown rule

Quality champion = **≥ +5 PASS over the champion's frozen Q50 baseline** at ≥15 tok/s
median gen (brain100 noise band was ±3, so +5 is signal). Speed is recorded but breaks
no ties; the speed champion keeps the daily-driver role regardless. If nothing clears
+5, the champion holds both crowns — a valid result.

## Planned coverage (reconciled at freeze against the manifest)

error-handling hardening, perf-with-a-correctness-trap, API-misuse repair, off-by-one/
boundary nests. Rough lang budget: rust ~12, python ~13, js ~9, ts ~8, shell ~8.
